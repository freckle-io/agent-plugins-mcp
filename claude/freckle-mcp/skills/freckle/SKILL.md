# Freckle through MCP

Freckle runs GTM data work: find companies and people, fill emails, phones and company facts through provider waterfalls, score and route rows, import CRM records, push ad audiences and watch Signals. Tool schemas and descriptions are authoritative for how to call things; this skill adds the GTM judgment they do not.

## Ground rules
- **Turn economy.** Every round trip costs the user seconds. These core Freckle tools are already loaded, so call them directly, never through `ToolSearch`: `workspace_context`, `creditUsage_getCurrentCredits`, `workflows_listWorkflows`, `workflows_getWorkflow`, `workflows_getWorkflowRevision`, `workflowNodes_listWorkflowNodes`, `workflowNodes_getWorkflowNodes`, `workbooks_createWorkbook`, `datasets_createWorkbookDataset`, `datasets_createCsvUploadUrl`, `datasets_importDatasetCsv`, `datasets_getDataset`, `datasets_createWorkflowDatasetConnection`, `workflows_buildWorkflow`, `workflowRuns_wait`, `datasets_waitForCsvImport`, `datasets_listDatasetEntries`, `datasets_getWorkflowDatasetConnection`, `datasets_listWorkflowDatasetConnectionRuns`, `datasets_runWorkflowDatasetConnectionEntries`, `datasets_triggerWorkflowDatasetConnection`. Their full names add the server prefix (`mcp__freckle__workspace_context`; use your server's name if it is not `freckle`). Only Freckle tools take that prefix: your own tools (`Skill`, `Bash`, `Read`, `ToolSearch`) keep their plain names. Every other Freckle tool is not loaded: its arguments are unknown until you load it, so before its first call load it (with any others you need) in one `ToolSearch` `select:` call with their full names. In your first turn call `workspace_context` together with your skill reads, then make independent tool calls in parallel in one message. Keep messages short: a plan is a few plain sentences, one diagram and one fields table with its cost; questions are numbered one-liners with a recommended answer; narrate at most one line per phase.
- Call `workspace_context` first; all work happens in that Workspace. For another Workspace, pick it from `workspace_context` and call `workspace_select`; no new sign-in is needed.
- Find named targets by id or name, archived ones too, and ask when a name is ambiguous. A missing target is not permission to create a replacement.
- When a Workflow the user made or edited and a Freckle-managed (Library) one do the same job, use the user's; say which and why. Freckle-managed Workflows have `managed: true`.
- Do what was asked and stop there: preview, import, build, run and ongoing automation are different scopes.
- Semantic judgments about rows against the user's written rules (classify, tier, flag) are a free `decision` node with those rules in its questions, also in a quick change to a saved Workflow; do not approximate them with keyword or regex lists in `code`. `code` handles deterministic parsing, normalization, exact numeric or enum rules and merging the answers.
- Discover provider capabilities through `workflowNodes_listWorkflowNodes` with a focused top-level `search` (e.g. `{ "search": "TheirStack" }`), then inspect the returned exact keys not already in its `nodeDetails` with `workflowNodes_getWorkflowNodes` as described in [BUILD.md](BUILD.md). Providers live inside the node catalog; an absent provider-named MCP tool says nothing about node availability. If ToolSearch is unavailable, use the exposed tools and their schemas directly instead of repeatedly scanning or dumping all tool descriptions.
- Confirm before spending credits: a plan with its cost, then a yes. That yes covers the run: show the sample; if the full run was already approved within the quoted max, continue; ask again only if the cost or scope changed, and before switching a connection to automatic. That yes covers one run of the quoted rows: running rows again, even after fixing the Workflow because of what the run showed, spends again and needs a new quote and yes, so report the problem and the fix and ask.
  If an already approved plan omitted a cost quote, that approval still authorizes its free construction. Build, validate, publish and create the manual connection without sampling or triggering rows; then quote the build's `runQuote` as its summary states it (the total for all rows, with the per-row figure and row count; known charges plus the extra charges when it is not bounded) and ask only for paid execution approval. Do not reopen the approved design or hold up free construction for a missing spend approval.
- A new build waits for a yes: send [freckle-plan](../freckle-plan/SKILL.md#approve)'s plan and make no create, import, connect or build call until the user approves it; an ask that already approves a stated plan is that yes. Look things up first. The plan covers the whole objective, every stage the user asked for (find, enrich, judge), even when the given rows look incomplete, masked or like test data: treat them as real, note a doubt in one line, and still send the plan. After the yes, build without asking again, and build every approved step (each provider, condition and gate): before publishing or starting rows, check the draft against the plan and add any missing step first; never publish or run a build that drops an approved step. Over 100 rows, run a sample and show it before the full run, even when the user says to just run; at 100 or fewer, run without one unless the user asks. A sample is the first 10 rows in the input Dataset's list order unless the user names a number ("a few", "some" or "a handful" still mean 10): `sampleRows`, or those entries' ids from `datasets_listDatasetEntries` (limit 10) in `datasets_runWorkflowDatasetConnectionEntries`.
- To run the rest after a sample (or every row not yet run), call `datasets_triggerWorkflowDatasetConnection`: it starts only the connection's pending rows, so no row runs twice. Never pick the remaining entry ids by hand. When exactly one active connection reads the input Dataset, pass that Dataset's id as `params.datasetId` instead of looking the connection up first; the result has the `connectionId` and `startedAt` that `workflowRuns_wait` takes (`since`).
- Report real outcomes: rows saved in the Workbook, the cost the server reports, failures and gaps as they are. A queued run is not a finished one.
- Secrets go only through the browser form `connections_setup` returns, never into chat, arguments or workflow JSON. A Dataset webhook URL is a credential: share it only with the requester.
- Talk to a GTM user: product words are fine; translate programming terms.

## Routes
- Anything to build (a call, notes, an idea, "build a workbook that…"): read [freckle-plan](../freckle-plan/SKILL.md) before your first reply, plan with it and get its approval before BUILD.md's first write.
- Company or people lists and CRM imports: [LIST.md](LIST.md). People at companies already in a Dataset are a workflow step (Apollo people), not a list search.
- Build, run or change workflows: [BUILD.md](BUILD.md). Change a saved workflow in place rather than rebuilding it.
- Running a workflow on a schedule, keeping it fresh, "on a cron", "make it automatic", pausing one, or "when the first finishes run the second": the app's Scheduled Workflows, in [BUILD.md](BUILD.md). In your reply, call it a Scheduled Workflow ("I set up a Scheduled Workflow that…").
- Ad audiences: [ADS.md](ADS.md). Signals: [SIGNALS.md](SIGNALS.md).
- A node needs an integration the org lacks: name it and send the `connections_setup` form.
- The user asks to snapshot, share or send this session or transcript to Freckle (feedback, a bug, "run the snapshot"): `snapshot_createUpload`, following its description. It needs a local shell; in a hosted chat, say it is unavailable there.

## Facts the tools do not show yet
- A run that waits in the queue for 24 hours while the Workspace has no credits is cancelled; a top-up does not revive it, so rerun those rows after topping up.
- Archived Workbooks and Datasets refuse imports and triggers; archiving a Workbook removes its Signals.
- Connections cannot be deleted and their mapping is fixed; a mapping change needs a new connection.
- A saved workflow's `id` (UUID) is what tools take; the draft's `workflowId` is only a slug.
